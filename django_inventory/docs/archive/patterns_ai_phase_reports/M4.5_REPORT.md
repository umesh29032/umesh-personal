## Verdict

(DEV-NICKAR "Nickar Back", on fold). The oldest honest blocker retired
with a named fix; fold is now a PATTERN CAPABILITY, used per-placement,

## What was built
- **adr-c.3 (conscious bump #3):** typed optional `features.fold_edge`
  ({p1_um,p2_um}, straight VERTICAL outline segment — the marker-table
  convention) in BOTH validator twins (lockstep); constant + model
  default bumped (migration **0015**); the pin test forced the
  deliberate edit exactly as designed.
- **fold_service (new, read-only + validation):** `validate_fold_edge`
  (vertices · adjacency · vertical) · `unfold_outline` (the opened
  piece = half + mirror about the fold line — DERIVED, never stored) ·
  `detect_fold_edge` (deterministic proposal; ties prefer the LEFT
  edge) · symmetry helper.
- **Studio:** editor FOLD-EDGE MODE (click a vertical outline edge;
  server re-validates via `edit_draft_geometry(fold_edge=…)`) ·
  R2-C one-shot proposals: on_fold piece without an edge → "Fold edge

  notes) · `mark_fold_capable` sets `on_fold` + edge through the
  single writers, asked once, permanent.
- **Capabilities contract (R2-A):** facade rows carry ONE derived
  `capabilities` dict (fold = on_fold ∧ edge · mirror · rotation ·
  seam · notches · count · optional) + `opened_outline_mm`/
  `opened_dims`/`fold_x_mm`. The DCT payload ships `caps` INSTEAD of
  loose flags (conscious test updates) — every consumer speaks one
  vocabulary; Blueprint/Studio stay the only editors.
- **Readiness law upgraded:** on_fold + confirmed + edge = READY;
  confirmed without an edge = blocker naming the fix ("mark the fold
  edge in the Studio"); geometry-less pieces keep the ordinary missing
  rules. Applied IDENTICALLY in both readiness twin bodies (the W1
  parity test still proves verbatim equality). The legacy generator
  keeps refusing folds with an honest pointer to the DCT.
- **Lay capability:** `double` split into `double_open`/`double_folded`
  (+ tubular = 2 fold edges); `LAY_FOLD_EDGES` recorded in layout
  params beside the multiplier; legacy `double` reads as open —
  byte-identical.
- **DCT fold placement (R2-B placement modes):** queue rows of
  fold-capable pieces offer the INSTANCE decision — [On fold — opens
  to 1/layer] / [Normally — cuts 2/placement]; fold-less lays offer
  [Import (unfolded)] using the derived opened outline. Queue math is
  PIECES-based (req/cut per factory truth); over-import refusals are
  fold-aware ("only 1 piece remaining — a normal placement cuts 2.
  Place it ON THE FOLD instead"). Fold placements: pinned to the
  crease (1-D drag, x-nudge refused), rotation locked ("the edge lives
  on the crease"), mirror locked ("the fold IS the mirror"),
  `col-fold` teal-dashed violation channel, dashed FOLD line(s) +
  label on the fabric, ⇋ label suffix "(fold)". Compact = y-gravity
  only for folds; Auto Place flows around them; the suggestion engine
  receives them as FIXED obstacles (zero engine changes) and never
  re-applies them.
- **Content math:** placements record `on_fold`; `marker_content` +
  provider count multiplier÷2 for fold placements (legacy no-flag =
  exact M4 math, tested byte-identical).
- **Blueprint:** `on_fold + is_pair` advisory chip ("a fold piece is
  symmetric by construction").

## Honest notes
- **Real bug caught + fixed during browser verify:** the detector
  picked the pattern's RIGHT vertical edge; pinning it to the left
  crease hung the body off-fabric (col-bound). Physics fix: a fold
  edge on the right half ⇒ AUTO-MIRROR at import (mirroring a half
  about its fold line = the identical opened piece); detector ties now
  prefer the left edge. Re-proven in-browser: pin x=0, zero
  violations.
- **Design flaw caught by my own test:** the planned "symmetric full
  piece → auto-mark fold-capable" was wrong — a full piece's fold line
  is its CENTERLINE, not an outline edge; auto-setting would double
  the unfold. v1 ships the honest version: an expert-judgment
  affordance keyed on a detected straight edge ("only you can tell —
  a pocket has straight edges too"). Centerline-symmetric full-piece
  advisory (re-digitize as half) = future.
- v1 boundaries (documented in the plan): fold edges vertical only ·
  fold placements pin to the LEFT crease (tubular's right edge = a
  future placement option) · engine slide-on-edge optimization
  consciously deferred.
- DEV artifacts: Nickar Back piece (on_fold, S+M halves 170×430,
  fold edges marked) + LAY-DEV-NICKAR-000002 + one unsaved single-lay
  session. Golden T-SHIRT untouched (foldless — readiness law change
  provably inert for it).
